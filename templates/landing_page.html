form_handlers.js 
// Fetch inventory dynamically based on resource selected
function fetchInventory(resource) {
    if (resource) {
        fetch('/get_inventory', {
            method: 'POST',
            headers: {
                'Content-Type': 'application/json',
            },
            body: JSON.stringify({ resource: resource }),
        })
        .then(response => response.json())
        .then(data => {
            displayInventory(data.inventory);
            calculateCleaningCharge(data.cleaning_charge);
            document.getElementById('inventory-section').style.display = 'block';
        })
        .catch(error => console.error('Error fetching inventory:', error));
    } else {
        document.getElementById('inventory-section').style.display = 'none';
    }
}

// Calculate and display cleaning charge based on selected resource and booking duration
function calculateCleaningCharge(dailyCharge) {
    const startDate = new Date(document.getElementById('start_date').value);
    const endDate = new Date(document.getElementById('end_date').value);

    if (!isNaN(startDate) && !isNaN(endDate)) {
        const timeDiff = endDate - startDate;
        const daysBooked = Math.ceil(timeDiff / (1000 * 60 * 60 * 24)) + 1;
        const totalCleaningCharge = daysBooked * dailyCharge;

        document.getElementById('cleaning-charge').textContent = 
            `Cleaning Charge: €${totalCleaningCharge}`;
        document.getElementById('cleaning-charge-input').value = totalCleaningCharge;
    } else {
        document.getElementById('cleaning-charge').textContent = "Cleaning Charge: N/A";
        document.getElementById('cleaning-charge-input').value = 0;
    }
}

Technical Features

Key programming challenges and their implementations

Authentication System

Security Implementation

Implemented secure user authentication with password hashing using Flask-Login and Werkzeug security. Role-based access control ensures that regular users and administrators have appropriate permissions. CSRF protection implemented on all forms.

Calendar Integration

Interactive Scheduling

Advanced calendar functionality using Syncfusion JavaScript library with server-side event population. Implements conflict detection algorithm to prevent double bookings and ensure resource availability. Features dynamic rendering of events with color coding.

Email Notification System

Automated Communications

Designed email notification system with HTML templates for booking confirmations, modifications, and cancellations. Integrated with SMTP service for reliable delivery. Implements asynchronous sending to prevent UI blocking during email operations.

Theming System

Dynamic Styling

Implemented a CSS variable-based theming system that enables consistent styling across the application. Created modular SCSS architecture with component-specific styles. Responsive design works on mobile, tablet, and desktop viewports.

Admin Dashboard

Data Visualization

Built comprehensive admin interface with usage analytics and resource management tools. Dynamic data visualization displays booking trends and resource utilization. CRUD operations for users, resources, and inventory management.

RESTful API

Backend Services

Designed RESTful API endpoints for asynchronous data fetching and state management. Implements JSON responses for inventory fetching, booking validation, and calendar data. Features proper error handling and status codes.

API Endpoints

RESTful services powering dynamic functionality

POST /get_inventory
Fetches available inventory items for a specific resource along with cleaning charge information.
Request Parameters:
  • resource string The name of the resource to fetch inventory for
Response:
  • inventory array List of inventory items with name, max_quantity
  • cleaning_charge float Daily cleaning charge for the resource
GET /get_bookings
Returns all bookings formatted for calendar display with appropriate color coding.
Response:
  • Array of events array Calendar events with Id, Subject, StartTime, EndTime, IsAllDay, Color
POST /submit_form
Processes booking form submission and creates a new booking in the database.
Request Parameters:
  • first_name string First name of the person making the booking
  • last_name string Last name of the person making the booking
  • email string Email address for communications
POST /confirm_cancellation/:booking_number
Validates cancellation code and processes booking cancellation if valid.
URL Parameters:
  • booking_number string Unique identifier for the booking
Request Parameters:
  • cancellation_code string Security code sent via email to confirm cancellation

Development Challenges

Technical problems encountered and their solutions

Preventing Double Bookings

Implemented a custom validation algorithm that checks for overlapping time slots when users attempt to book a resource. Created database queries with date range constraints to identify conflicts before allowing new bookings.

Dynamic Inventory Management

Designed a dynamic form system that loads available inventory items based on the selected resource. Implemented JavaScript fetch API for asynchronous data loading and form updates without page reloads.

Secure Booking Modification

Created a multi-step verification process for booking modifications and cancellations to prevent unauthorized changes. Implemented unique cancellation codes delivered via email for secure verification.

Calendar Rendering Performance

Optimized calendar data loading to handle large numbers of bookings without performance degradation. Implemented lazy loading and pagination of event data with asynchronous updates.
